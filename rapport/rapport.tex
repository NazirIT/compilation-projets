\section{Introduction}
%=============================================================

\subsection{Contexte et Motivation}

Dans le cadre du module de \textbf{Théorie des Langages et Compilation} de la formation GeIT 2 à l'Institut Polytechnique de Saint-Louis (IPSL), nous avons conçu et implémenté un \textbf{Système de Gestion des Notes} (SGN). Ce projet a pour objectif de mettre en pratique les concepts fondamentaux enseignés tout au long du semestre~:

\begin{itemize}[leftmargin=1.5em]
  \item La conception d'une \textbf{grammaire formelle} pour un langage dédié (DSL),
  \item L'implémentation d'un \textbf{analyseur lexical} avec l'outil \texttt{Flex},
  \item L'implémentation d'un \textbf{analyseur syntaxique et sémantique} avec \texttt{Bison},
  \item La construction d'une \textbf{représentation intermédiaire} (Arbre Syntaxique Abstrait + table de symboles),
  \item La réalisation d'une \textbf{interface graphique} Python reliant le frontal visuel au compilateur C.
\end{itemize}

\subsection{Objectifs du Projet}

Le système doit analyser des fichiers de notes étudiantes au format \texttt{.sgn} (format défini pour le projet), vérifier leur conformité syntaxique et sémantique, calculer automatiquement les moyennes, rangs et mentions, puis exporter ces résultats via une interface graphique.

À la fin de ce projet, nous sommes capables de~:
\begin{itemize}[leftmargin=1.5em]
  \item Définir et analyser un \textbf{langage dédié} (DSL),
  \item Interconnecter un \textbf{compilateur C} avec un \textbf{frontend Python},
  \item Gérer proprement les \textbf{erreurs} à tous les niveaux (lexical, syntaxique, sémantique).
\end{itemize}

\section{Spécification du Langage \texttt{.sgn}}
%=============================================================

\subsection{Description du Domaine}

Le langage \texttt{.sgn} est un \textbf{DSL} (Domain-Specific Language) structuré pour décrire les notes d'étudiants répartis sur trois niveaux d'études~:

\begin{center}
\begin{tabular}{clll}
\toprule
\textbf{Niveau} & \textbf{Désignation} & \textbf{Modules types} & \textbf{Semestres} \\
\midrule
L1 & Première année de Licence & Maths, Algo, Réseaux, Physique & S1, S2 \\
L2 & Deuxième année de Licence & POO, BDD, Systèmes, Stats     & S3, S4 \\
L3 & Troisième année de Licence & Compilation, IA, Génie Logiciel & S5, S6 \\
\bottomrule
\end{tabular}
\end{center}

Chaque étudiant possède un \textbf{matricule unique}, un nom complet, et une liste de notes par module avec un coefficient associé.

\subsection{Structure d'un Fichier d'Entrée}

Un fichier \texttt{.sgn} suit une organisation hiérarchique stricte~: le fichier commence obligatoirement par la déclaration de l'année académique, puis liste les niveaux, chacun contenant des étudiants avec leurs semestres et modules.

\begin{lstlisting}[caption={Extrait d'un fichier .sgn valide}, style=sgn, label=lst:exemple-sgn]
-- Fichier notes : Annee academique 2025-2026
ANNEE "2025-2026"

NIVEAU L1 {
  ETUDIANT {
    MATRICULE : "L1-2025-001"
    NOM : "DIALLO Mamadou"
    PRENOM : "Mamadou"
    SEMESTRE S1 {
      MODULE "Algorithmique" COEF 3 NOTE 14.5
      MODULE "Mathematiques" COEF 4 NOTE 12.0
      MODULE "Architecture"  COEF 2 NOTE 16.0
      MODULE "Anglais"       COEF 1 NOTE 15.0
    }
    SEMESTRE S2 {
      MODULE "Programmation C" COEF 3 NOTE 13.5
      MODULE "Logique"         COEF 3 NOTE 11.0
      MODULE "Reseaux"         COEF 2 NOTE 17.0
    }
  }
}
\end{lstlisting}

Les lignes commençant par \texttt{--} sont des \textbf{commentaires} et sont ignorées par l'analyseur.

\subsection{Grammaire Formelle (BNF)}

La grammaire complète du langage \texttt{.sgn} est définie ci-dessous~:

\begin{lstlisting}[caption={Grammaire BNF du langage .sgn}, style=sgn, label=lst:bnf]
<programme>       ::= ANNEE STRING <liste_niveaux>
<liste_niveaux>   ::= <niveau> | <liste_niveaux> <niveau>
<niveau>          ::= NIVEAU <id_niveau> '{' <liste_etudiants> '}'
<id_niveau>       ::= L1 | L2 | L3
<liste_etudiants> ::= <etudiant> | <liste_etudiants> <etudiant>
<etudiant>        ::= ETUDIANT '{' <champs_etudiant> <liste_semestres> '}'
<champs_etudiant> ::= MATRICULE ':' STRING
                      NOM ':' STRING
                      PRENOM ':' STRING
<liste_semestres> ::= <semestre> | <liste_semestres> <semestre>
<semestre>        ::= SEMESTRE <id_sem> '{' <liste_modules> '}'
<id_sem>          ::= S1 | S2 | S3 | S4 | S5 | S6
<liste_modules>   ::= <module> | <liste_modules> <module>
<module>          ::= MODULE STRING COEF ENTIER NOTE REEL
<STRING>          ::= '"' [^"]* '"'
<REEL>            ::= [0-9]+ ('.' [0-9]+)?
<ENTIER>          ::= [0-9]+
\end{lstlisting}

La grammaire est de type \textbf{LL(1)} compatible, ce qui la rend propice à une implémentation avec Bison (analyseur LALR(1)).

\subsection{Tokens Lexicaux}

Le tableau suivant recense l'ensemble des tokens reconnus par l'analyseur lexical~:

\begin{center}
\begin{tabular}{llll}

\section{Implémentation de l'Analyseur Lexical (Flex)}
%=============================================================

\subsection{Principes Généraux}

L'analyseur lexical est implémenté dans le fichier \texttt{src/lexer.l}. Il constitue le premier maillon de la chaîne de compilation~: il lit le flux de caractères du fichier \texttt{.sgn} et le découpe en \textbf{tokens} significatifs qui sont transmis à l'analyseur syntaxique Bison.

Flex génère automatiquement le fichier \texttt{lex.yy.c} à partir de \texttt{lexer.l}. Les deux options Flex essentielles utilisées sont~:
\begin{itemize}[leftmargin=1.5em]
  \item \texttt{\%option noyywrap} — pas de fichier multiple à enchaîner,
  \item \texttt{\%option yylineno} — comptage automatique des numéros de ligne pour les messages d'erreur.
\end{itemize}

\subsection{Définitions de Patterns}

Les macros suivantes simplifient l'écriture des règles~:

\begin{lstlisting}[caption={Macros de patterns dans lexer.l}, style=flex, label=lst:macros]
CHIFFRE     [0-9]
BLANC       [ \t\r]+
REEL_DEF    {CHIFFRE}+("."{CHIFFRE}+)?
STRING_DEF  \"[^"\n]*\"
\end{lstlisting}

Le pattern \texttt{REEL\_DEF} reconnaît à la fois les entiers (\texttt{14}) et les réels (\texttt{14.5}). La distinction entre \texttt{ENTIER} et \texttt{REEL} est faite en vérifiant la présence d'un point décimal via \texttt{strchr()}.

\subsection{Règles Lexicales}

\begin{lstlisting}[caption={Extrait des règles de reconnaissance dans lexer.l}, style=flex, label=lst:regles-lex]
"--"[^\n]*      { /* commentaire : ignorer */ }

"ANNEE"         { return ANNEE;      }
"NIVEAU"        { return NIVEAU_KW;  }
"ETUDIANT"      { return ETUDIANT;   }
"MATRICULE"     { return MATRICULE;  }
"NOM"           { return NOM_TOK;    }
"PRENOM"        { return PRENOM_TOK; }
"SEMESTRE"      { return SEMESTRE;   }
"MODULE"        { return MODULE_KW;  }
"COEF"          { return COEF;       }
"NOTE"          { return NOTE;       }

"L1"            { return L1; }
"L2"            { return L2; }
"L3"            { return L3; }
"S1"            { return S1; }  /* ... S2..S6 idem */

{REEL_DEF}      {
    if (strchr(yytext, '.') != NULL) {
        yylval.reel = atof(yytext);
        return REEL;
    } else {
        yylval.entier = atoi(yytext);
        return ENTIER;
    }
}

{STRING_DEF}    {
    int len = yyleng - 2;
    yylval.chaine = malloc(len + 1);
    strncpy(yylval.chaine, yytext + 1, len);
    yylval.chaine[len] = '\0';
    return STRING;
}

{BLANC}         { /* ignorer espaces et tabulations */ }
"\n"            { /* saut de ligne gere par yylineno  */ }

.               {
    /* Caractere non reconnu -> erreur lexicale */
    char msg[64];
    snprintf(msg, sizeof(msg),
             "Caractere inattendu : '%s'", yytext);
    erreur_lexicale(msg, yylineno);
    return ERREUR_LEX;
}
\end{lstlisting}

\textbf{Ordre de priorité} : Flex applique les règles dans l'ordre de leur déclaration en cas d'ambiguïté. Les mots-clés sont donc listés \textit{avant} la règle générique \texttt{.} (catch-all), garantissant leur reconnaissance prioritaire.

\subsection{Gestion des Erreurs Lexicales}

Tout caractère non reconnu par les patterns précédents déclenche la règle \texttt{.} et appelle \texttt{erreur\_lexicale()}~:

\begin{lstlisting}[caption={Fonction de signalement d'erreur lexicale}, style=c, label=lst:err-lex]
void erreur_lexicale(const char *msg, int ligne) {
    fprintf(stderr, "[ERREUR LEXICALE] Ligne %d : %s\n",
            ligne, msg);
}
\end{lstlisting}

Le message est écrit sur \texttt{stderr} (séparé du flux JSON sur \texttt{stdout}), ce qui permet à Python de les capturer indépendamment.

\subsection{Mode Test Autonome}

Le fichier \texttt{lexer.l} intègre un mode test conditionnel (\texttt{\#ifdef TEST\_LEXER\_ONLY}) permettant de le compiler seul et de vérifier la liste de tokens produits avant même d'intégrer Bison.

\section{Implémentation de l'Analyseur Syntaxique et Sémantique (Bison)}
%=============================================================

\subsection{Architecture du Fichier \texttt{parser.y}}

Le fichier \texttt{src/parser.y} est divisé en quatre sections canoniques~:

\begin{enumerate}[leftmargin=1.5em]
  \item \textbf{Déclarations C} — includes, variables globales de contexte,
  \item \textbf{Déclarations Bison} — union sémantique, liste des tokens et types,
  \item \textbf{Règles de grammaire} — productions BNF avec actions sémantiques,
  \item \textbf{Fonctions C} — \texttt{yyerror}, fonctions de calcul et de génération JSON.
\end{enumerate}

\subsubsection{Variables Globales de Contexte}

\begin{lstlisting}[caption={Variables de contexte dans parser.y}, style=c, label=lst:globals]
Programme     g_programme;           /* toutes les donnees parsees */
TableSymboles g_table;               /* detection des doublons     */
ASTNode      *g_ast_racine = NULL;   /* racine de l'AST            */
int           g_erreurs    = 0;      /* compteur global d'erreurs  */

Niveau        *g_niveau_courant   = NULL;
Etudiant      *g_etudiant_courant = NULL;
Semestre      *g_semestre_courant = NULL;
\end{lstlisting}

Ces pointeurs de contexte sont mis à jour au fil du parsing pour éviter une navigation coûteuse dans les structures imbriquées.

\subsection{Règles Syntaxiques et Actions Sémantiques}

Chaque règle de production est associée à un bloc d'action C exécuté lors de la réduction. Voici les points clés~:

\subsubsection{Niveau}
À l'ouverture d'un bloc \texttt{NIVEAU}, un slot est réservé dans \texttt{g\_programme.niveaux[]} et un nœud AST de type \texttt{NODE\_NIVEAU} est créé et rattaché à la racine. En fin de bloc, la fonction \texttt{calculer\_rangs()} trie et attribue les rangs aux étudiants du niveau.

\subsubsection{Étudiant}
À l'ouverture d'un bloc \texttt{ETUDIANT}, un slot est réservé et un nœud \texttt{NODE\_ETUDIANT} est créé. À la fermeture du bloc, la moyenne annuelle et la mention sont calculées automatiquement.

\subsubsection{Module — Vérifications Sémantiques Immédiates}
\begin{lstlisting}[caption={Action sémantique d'un module}, style=bison, label=lst:module-sem]
module
    : MODULE_KW STRING COEF ENTIER NOTE REEL
        {
            verifier_note($6, yylineno);  /* note dans [0,20] */
            verifier_coef($4, yylineno);  /* coef >= 1        */

            int idx = g_semestre_courant->nb_modules++;
            strncpy(g_semestre_courant->modules[idx].nom, $2, ...);
            g_semestre_courant->modules[idx].coef = $4;
            g_semestre_courant->modules[idx].note = $6;

            ast_ajouter_enfant(g_ast_semestre_courant,
                ast_creer_module($2, $4, $6, yylineno));
            free($2);
        }
    ;
\end{lstlisting}

\subsection{Vérifications Sémantiques}

Quatre règles sémantiques sont appliquées~:

\begin{center}
\renewcommand{\arraystretch}{1.3}
\begin{tabular}{clll}
\toprule
\textbf{N°} & \textbf{Règle} & \textbf{Condition} & \textbf{Message d'erreur} \\
\midrule
1 & Note valide      & $0.0 \le \text{note} \le 20.0$  & \texttt{[ERREUR SEMANTIQUE] Note hors intervalle} \\
2 & Coefficient      & $\text{coef} \ge 1$             & \texttt{[ERREUR SEMANTIQUE] Coefficient invalide} \\
3 & Semestre/Niveau  & L1→S1,S2 ; L2→S3,S4 ; L3→S5,S6 & \texttt{[ERREUR SEMANTIQUE] Semestre incompatible} \\
4 & Unicité matricule & Pas de doublon dans un niveau   & \texttt{[ERREUR SEMANTIQUE] Matricule deja utilise} \\
\bottomrule
\end{tabular}
\end{center}

\subsubsection{Gestion des Erreurs Syntaxiques}

La fonction \texttt{yyerror()} est automatiquement appelée par Bison lors d'une erreur syntaxique~:

\begin{lstlisting}[caption={Fonction yyerror}, style=c, label=lst:yyerror]
void yyerror(const char *msg) {
    fprintf(stderr, "[ERREUR SYNTAXIQUE] Ligne %d : %s\n",
            yylineno, msg);
    g_erreurs++;
}
\end{lstlisting}

\subsection{Règles de Calcul}

\subsubsection{Moyenne Pondérée d'un Semestre}

\begin{equation}
  \overline{M}_s = \frac{\displaystyle\sum_{i=1}^{n} c_i \times n_i}{\displaystyle\sum_{i=1}^{n} c_i}
  \label{eq:moy-sem}
\end{equation}

où $c_i$ est le coefficient du module $i$ et $n_i$ sa note.

\subsubsection{Moyenne Annuelle}

\begin{equation}
  \overline{M}_a = \frac{1}{S} \sum_{s=1}^{S} \overline{M}_s
  \label{eq:moy-an}
\end{equation}

$S$ est le nombre de semestres validés par l'étudiant.

\subsubsection{Décision de Passage et Mentions}

\begin{center}
\renewcommand{\arraystretch}{1.4}
\begin{tabular}{cll}
\toprule
\textbf{Intervalle} & \textbf{Décision} & \textbf{Mention} \\
\midrule
$\overline{M}_a \ge 16{,}0$ & Admis & Très Bien \\
$14{,}0 \le \overline{M}_a < 16{,}0$ & Admis & Bien \\
$12{,}0 \le \overline{M}_a < 14{,}0$ & Admis & Assez Bien \\
$10{,}0 \le \overline{M}_a < 12{,}0$ & Admis & Passable \\
$\overline{M}_a < 10{,}0$ & Ajourné & — \\
\bottomrule
\end{tabular}
\end{center}

\subsubsection{Classement (Rang)}

Le rang est calculé par un algorithme de comparaison croisée~: pour chaque étudiant $i$, son rang est le nombre d'étudiants $j \ne i$ ayant une moyenne annuelle strictement supérieure, plus un.

\begin{lstlisting}[caption={Algorithme de calcul des rangs}, style=c, label=lst:rangs]
void calculer_rangs(Niveau *niv) {
    int i, j, n = niv->nb_etudiants;
    for (i = 0; i < n; i++) niv->etudiants[i].rang = 1;
    for (i = 0; i < n; i++)
        for (j = 0; j < n; j++)
            if (i != j &&
                niv->etudiants[j].moyenne_annuelle >
                niv->etudiants[i].moyenne_annuelle)
                niv->etudiants[i].rang++;
}
\end{lstlisting}

\subsection{Arbre Syntaxique Abstrait (AST)}

Nous avons implémenté un AST générique à enfants dynamiques. Chaque nœud est représenté par la structure \texttt{ASTNode} définie dans \texttt{ast.h}~:

\begin{lstlisting}[caption={Structure d'un nœud AST dans ast.h}, style=c, label=lst:ast-struct]
typedef enum {
    NODE_PROGRAMME,   /* racine                         */
    NODE_NIVEAU,      /* L1, L2 ou L3                   */
    NODE_ETUDIANT,    /* bloc etudiant                  */
    NODE_MATRICULE,   /* feuille : matricule            */
    NODE_NOM,         /* feuille : nom                  */
    NODE_PRENOM,      /* feuille : prenom               */
    NODE_SEMESTRE,    /* S1..S6                         */
    NODE_MODULE,      /* module avec coef et note       */
    NODE_ANNEE        /* valeur de l'annee academique   */
} NodeType;

typedef struct ASTNode {
    NodeType  type;
    NodeValue valeur;       /* union : chaine | entier | reel */
    int       coef;         /* pour NODE_MODULE               */
    double    note;         /* pour NODE_MODULE               */
    struct ASTNode **enfants;
    int              nb_enfants;
    int              capacite;
    int              ligne;
} ASTNode;
\end{lstlisting}

\subsection{Présentation Générale}

L'interface graphique est développée en \textbf{Python 3} avec la bibliothèque \textbf{PyQt5}. Elle offre un environnement de travail complet pour charger, éditer, analyser et exporter les fichiers \texttt{.sgn}.

L'application suit le modèle \textbf{MVC} (Modèle-Vue-Contrôleur)~:
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Modèle} — données JSON retournées par le binaire C,
  \item \textbf{Vue} — widgets Qt (éditeur, tableau, console) définis dans \texttt{interface.py},
  \item \textbf{Contrôleur} — méthodes de \texttt{SGNAnalyzer} dans \texttt{interface.py} et pont dans \texttt{parser\_bridge.py}.
\end{itemize}

\subsection{Architecture des Fichiers Python}

\begin{center}
\begin{tabular}{ll}
\toprule
\textbf{Fichier} & \textbf{Rôle} \\
\midrule

\subsection{Communication Python $\leftrightarrow$ C}

La communication est réalisée exclusivement via \texttt{subprocess.run()}~:

\begin{lstlisting}[caption={Pont Python–C dans parser\_bridge.py}, style=python, label=lst:bridge]
import subprocess, json

def run_parser(filepath):
    result = subprocess.run(
        ["./src/sgn", filepath],
        capture_output=True,
        text=True
    )
    data = json.loads(result.stdout)
    errors = result.stderr.strip().splitlines()
    data["erreurs"] = errors if errors else []
    return data
\end{lstlisting}

\begin{itemize}[leftmargin=1.5em]
  \item \textbf{stdout} $\rightarrow$ JSON structuré (résultats d'analyse),
  \item \textbf{stderr} $\rightarrow$ messages d'erreurs (lexicales / syntaxiques / sémantiques),
  \item \textbf{returncode} $\rightarrow$ \texttt{0} si succès, \texttt{1} si erreurs détectées.
\end{itemize}

\section{Conclusion}
%=============================================================

\subsection{Bilan Technique}

Ce projet nous a permis de maîtriser l'ensemble de la chaîne de compilation~: de la définition d'un langage formel jusqu'à son intégration dans une application graphique complète.

\textbf{Points forts de l'implémentation~:}
\begin{itemize}[leftmargin=1.5em]
  \item L'\textbf{analyseur lexical} reconnaît tous les tokens du langage et signale précisément les erreurs avec le numéro de ligne.
  \item L'\textbf{analyseur syntaxique} valide la structure hiérarchique et la \textbf{table de symboles} détecte les doublons de matricule.
  \item Les \textbf{vérifications sémantiques} couvrent les quatre cas demandés (notes, coefficients, semestres, doublons).
  \item L'\textbf{AST} permet de calculer les rangs après avoir parsé l'ensemble d'un niveau.
  \item La \textbf{sortie JSON} sur \texttt{stdout} et les \textbf{erreurs sur stderr} constituent une interface propre et découplée entre le compilateur C et le frontend Python.
\end{itemize}

\subsection{Difficultés Rencontrées}

\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Gestion mémoire en C} : la construction du JSON sans bibliothèque tierce a nécessité l'écriture d'une fonction d'échappement (\texttt{json\_string\_safe()}) pour traiter les caractères spéciaux.
  \item \textbf{Synchronisation stdout/stderr} : s'assurer que Python capture correctement les deux flux séparément via \texttt{subprocess.run(..., capture\_output=True)}.
  \item \textbf{Règles de priorité Flex} : l'ordre des règles est critique pour que les mots-clés soient reconnus avant la règle catch-all \texttt{.}.
  \item \textbf{Gestion des contextes Bison} : l'utilisation de pointeurs globaux de contexte (niveau, étudiant, semestre courants) a simplifié considérablement la gestion des structures imbriquées.
\end{itemize}

\subsection{Perspectives d'Évolution}

Le système est aisément extensible~:
\begin{itemize}[leftmargin=1.5em]
  \item \textbf{Nouveaux champs} : ajout de crédits ECTS, d'UE (Unités d'Enseignement), ou de modules d'option sans modifier la structure de base.
  \item \textbf{Export PDF} : génération directe d'un relevé de notes depuis l'interface Python.
  \item \textbf{Support multi-fichiers} : fusion de plusieurs fichiers \texttt{.sgn} en un rapport global.
  \item \textbf{Récupération d'erreur Bison} : l'implémentation du token \texttt{error} de Bison permettrait de continuer l'analyse après une erreur syntaxique.
\end{itemize}
